# Internationalization

## Configuration

`config/packages/translation.yaml`:

```yaml
framework:
    default_locale: es
    translator:
        default_path: "%kernel.project_dir%/translations"
        fallbacks:
            - es
```

`config/services.yaml` exposes the `LOCALES` environment variable as the parameter `locales`, used by:

- `App\EventSubscriber\LocaleSubscriber` (allow-list of accepted locales).
- `config/packages/twig.yaml` (Twig global `locales`).
- `App\Controller\Admin\DashboardController::configureDashboard()` to build the EasyAdmin language switcher.

`.env` ships `LOCALES='es|en'`.

## Locale resolution

`App\EventSubscriber\LocaleSubscriber` priority 40 picks the request locale per main request:

1. If `_locale` is provided by the route or query, and it is in the allow-list, persist it on the session.
2. Read the session value (or fall back to `default_locale`).
3. Validate against the allow-list once more.
4. Apply with `Request::setLocale($locale)`.

The admin dashboard route is `/admin/{_locale}` so the locale is part of the URL there; on the public site the value is whatever the user persisted during their session.

See [http-subscribers](06-http-subscribers.md#localesubscriber).

## Translation files

```
translations/
├── messages.es.yaml                # Application strings
├── EasyAdminBundle.es.yaml         # EA overrides
├── ArkounayUxMediaBundle.es.yaml   # Bundle overrides
└── validators/
    └── validators.es.yaml          # Symfony Validator messages
```

`messages.es.yaml` follows a stable shape; the most relevant top-level keys are:

| Key                                      | Used by                                                                      |
| ---------------------------------------- | ---------------------------------------------------------------------------- |
| `app.messages.*`                         | Flash messages thrown from controllers / subscribers                         |
| `admin.*`                                | Admin chrome strings (home, profile)                                         |
| `public.*`                               | Public-site strings (home, login, register, reset, privacy, cookies)         |
| `email.*`                                | Subject / content fragments for transactional emails (see [email](14-email.md)) |
| `entities.<entity>.singular` / `.plural` | Entity labels resolved by `AbstractCrudController`                           |
| `entities.<entity>.sections.<section>`   | Form / detail panel headings                                                 |
| `entities.<entity>.fields.<field>`       | Field labels                                                                 |
| `entities.<entity>.actions.<action>`     | Custom action labels (e.g. `impersonate`)                                    |
| `entities.role.permissions.<permission>` | Friendly labels for non-CRUD permissions                                     |
| `entities.user.fields.genders.<case>`    | Backed enum (`UserGender`) translation keys                                  |

`AbstractCrudController` exposes the convention helpers `transEntitySingular()`, `transEntityPlural()`, `transEntitySection()`, `transEntityAction()` and `transEntityField()`, all rooted at `entities.{transEntity}.*`.

`UserGender` (`src/Entity/Enum/UserGender.php`) implements `TranslatableInterface` and resolves keys under `entities.user.fields.genders.{caseName}`.

## Adding a new locale

1. Append the code to `LOCALES` in `.env` / `.env.local` (e.g. `LOCALES='es|en|fr'`).
2. Create `translations/messages.<locale>.yaml` (and any bundle override files needed) by copying from `messages.es.yaml`.
3. Translate `validators/validators.<locale>.yaml`.
4. The locale will appear automatically in the EasyAdmin switcher and pass the `LocaleSubscriber` allow-list.
